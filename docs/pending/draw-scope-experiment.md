# Discord draw scope experiment — held

This isolated experiment is not a release candidate. The schema alongside it is an unnumbered copy of the existing 0033 proposal. It has not been applied remotely. Its place among other pending migrations, deployed-worker compatibility and rollback still need review.

The transaction captures an epoch before scope resolution and checks it, the signed Discord principal, current membership and the exact installation configuration inside the draw batch. Local tests inject policy, identity, membership, owner assignment, collection grant, draft link, card lifecycle, pool and trigger changes immediately before the batch. Those tests are not proof of Discord delivery authorization: there is still an external send race and render lineage is not qualified.

An explicitly revoked Discord identity remains denied; onboarding will not re-enable it. The existing OAuth callback links whenever a session is present, has no explicit restore intent or recent-strong-auth gate, and cannot reinsert the same Discord ID because of the unconditional tenant/Discord uniqueness constraint. There is no qualified self-service or administrator restoration path in this candidate. The error directs the player to the Bot Owner for help; it does not promise that reconnecting will restore access.

Historical Discord replay and initial recovery are neutral and withhold details, including where the player still has access. Known or uncertain outcomes provide a receipt button that invokes the existing current-scope redelivery without a second draw. A signed lost-acknowledgement test confirms denial while the collection is a draft and the original serial after publication is restored. This is a stopgap, not complete product behavior: redelivery still has the documented external send race and incomplete AI-off lineage. An independently reviewed live-authorized, selected-card-only receipt reader must restore direct recovery without disclosing historic odds. Concurrent same-key draws must preserve one debit and avoid asserting that no charge occurred when the outcome is ambiguous.

For the experiment, a temporary directory outside the repository contained copies of migrations 0001–0027 plus this proposal named as the next test migration. Set `FOILBURY_TEST_MIGRATIONS` to a new `/tmp/foilbury-epoch-test-*` directory containing those copies before running `pnpm exec vitest run --config vitest.epoch.local.config.ts tests/workers/discord-recovery.test.ts tests/workers/discord-scope.test.ts tests/workers/discord-epoch-experiment.test.ts`. This configuration is local-only and the proposal must not be committed as a production migration. The actual held admin candidate was tested separately with this complete test migration, where 43 capability and race tests passed. This does not establish compatibility of every writer or migration ordering.
