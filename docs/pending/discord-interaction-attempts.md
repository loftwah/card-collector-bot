# Discord interaction attempts — isolated prototype, held

The current interaction row is keyed by Discord interaction ID, while a signed delivery can be retried and overlap its earlier execution. `recordInteractionFinish` and `markDeliveryVisibility` do not identify the execution that produced an outcome. The failing `overlapping old attempt` test demonstrates an older empty-pool result taking ownership of a later successful committed draw. The parent epoch experiment is preserved separately.

The adjacent SQL is an **unnumbered test-only schema**, not an approved production migration. The isolated prototype adds an attempt ID to each handler execution, atomically records attempt completion and visibility, and conditionally updates the parent using its current attempt ID. Draws are never authorized by attempt logging. A sound implementation must meet the following contract:

1. After signature verification, each actual handler execution receives a fresh unpredictable attempt ID. Insert the verified application, guild, Discord user, interaction ID and start time in an attempt row; a retry must not take ownership of an earlier attempt. A different principal presenting the same interaction ID cannot change another actor's attempt or its parent projection.
2. Carry that exact ID through both the Effect draw workflow and generic handler, including early identity failure, cancellation, asynchronous delivery, top-level defect fallback and non-deferred execution. No later helper may look up or guess the "current" attempt ID.
3. Finish and visibility belong to one attempt. Write both in one conditional statement `WHERE attempt_id=? AND status='processing'` with the verified parent identifiers. Zero rows means a stale, expired or already-finished attempt: do not overwrite another outcome or invent delivery. Redelivery is a distinct signed interaction and a distinct attempt.
4. Expiry is per attempt and conditionally changes only still-processing attempts. Late completion cannot overwrite its expired state; if its draw commits later, the durable draw remains authoritative and the late result needs a separate reconciliation event, rather than silently changing another attempt's delivery outcome. Do not retry a possibly committed draw as a new purchase.
5. The durable draw and debit, joined to the signed Discord principal and installation, establish whether an opening committed. Do not infer non-commit from absence during an in-flight attempt. Expose the original committed draw and each attempt outcome separately; any aggregate status must explicitly specify which attempt and must never turn a committed draw into a failed draw. The current single mutable parent status/visibility must not be represented as original delivery history.
6. Receipt persistence is not attempt ownership: retain idempotent draw and receipt recovery and authorize the current actor, channel, collection, lifecycle and media before disclosure. The external send race and AI provenance remain separate problems. Logging storage failure must not produce fabricated non-commit or allow duplicate draws.
7. Stage and roll out schema with compatible old and new Workers, decide the ordered migration and rollback before applying it, and audit indexes and retention. Existing rows have no reconstructable per-attempt history and must be labelled unknown rather than backfilled as if observed.

The previously failing overlap reproduction now passes. Targeted tests cover wrong-principal projection isolation, expiry followed by late commit, a simulated Worker disappearance followed by scheduled reconciliation, a failed initial logging write with later authorized receipt recovery, current-scope replay, and duplicate same-key debit. The test-only scheduled sweep uses an indexed 50-row composite-key page, fixed cycle high-water mark, generation-protected CAS and bounded expiry batches. A local test traverses 1,200 matching-timestamp records over 24 passes while 40 newer records arrive after each pass; other tests cover an unmatched prefix, overlapping passes, full-cycle ABA and query plans. The composite range is necessary to avoid repeatedly traversing an equal-timestamp prefix. Production-scale scan and latency behavior, clock ordering and the full SQL plan still need independent review; no hard remote-work claim is made. If initial logging fails, the draw can be recovered by its authorized receipt, but the missing original interaction row is not reconstructed. This is still incomplete: opposite-order concurrency, cancellation versus finish, late commit after logging failure, visibility write failures, rollout compatibility and load/retention need further qualification. The aggregate row is a projection; its delivery fields must not be presented as exhaustive per-attempt history. No schema has been applied remotely.

The candidate also experiments with a version-2 same-key insufficient-funds terminal marker, bound to the original scope epochs and readable only with current identity and installation authority. It permits truthful low-funds guidance without a second debit, but existing and rollback Workers ignore idempotency status or recognize a different marker version. The writer is hard-disabled in production and remains held until a compatible reader has been staged and verified across every active and rollback Worker, and marker retention/recovery is defined. No local result is live Discord, migration, load or product acceptance.
